# API 명세 초안
> 원본: [기획서 12장](./planning.md) · 2026-11-10 기준 초안. 팀 확정 전 변경될 수 있음
> 실제로 동작하는 API(요청·응답·오류)는 [api-reference.md](./api-reference.md) (PR #18 백엔드 기준)


모든 경로는 API Gateway를 거침. 보드에서 3\~6번은 /api/v1 접두어가 빠져 있어 통일을 제안함.

| # | 메서드·경로 | 화면 | 담당 서비스 (C4) | 응답 핵심 |
| --- | --- | --- | --- | --- |
| 1 | POST /api/v1/vehicle-lookups | A① | 진단 (→ 생산 연동) | vehicleId·profileId 또는 미등록 안내 |
| 2 | POST /api/v1/repair-jobs | A① A② | 진단 (→ 정비 기록 이력) | jobId, 후보, 공식 순서, 관측 비율, n |
| 3 | POST /api/v1/repair-jobs/{id}/tasks | A③ | 3D 가이드 | taskId, 절차 버전, 단계, 모델·2D 경로 |
| 4 | GET /api/v1/procedure-steps/{id}/knowledge | A③ 단계 팁 | knowledge (D22) | 공식 설명과 구분된 팁·제조사 답변 |
| 5 | PUT /api/v1/tasks/{id}/steps/{stepId}/ack | A③ 고전압 | 3D 가이드 (Safety Warning Manager) | 사용자·절차 버전·확인 시각 저장, 다음 단계 허용 |
| 6 | PUT /api/v1/repair-jobs/{id}/completion | A④ | 정비 기록 (공개 동의 메모는 → knowledge 팁 등록) | 검증 후 한 트랜잭션 저장, 같은 재전송은 중복 없음 |
| 7 | GET /api/v1/manufacturer/metrics | B | 분석 (→ 정비 기록 집계 조회) | 식별정보 없는 지표, 표본 수, 갱신 시점 |
| 8 | POST /api/v1/procedure-steps/{id}/knowledge | A③ 팁 남기기 | knowledge (D22) | 작성한 팁과 공개 여부. 비공개 팁은 작성자만 봄 |

8번은 프론트(PR #8)가 단계 팁 남기기에 쓰면서 추가함. 지금은 목 API(`frontend/src/api`)가 같은 인터페이스로 1\~8번을 흉내 냄.

백엔드(PR #18, D25)는 1\~6·8번을 구현함 (7번 미구현). 2번 요청은 `dtcCode` 하나이고, 담당 서비스 열은 모놀리스 안의 같은 이름 모듈로 읽으면 됨.

구현에서 추가한 API 9\~15 (PR #18, D25): 화면이 목 데이터를 직접 읽던 부분과 이어하기·취소·진행 저장을 API로 뺌. 모두 정비사 화면용이고 사용자 구분은 `X-User-Id` 헤더 (인증 L1\~L3 전까지).

| # | 메서드·경로 | 화면 | 담당 모듈 | 응답 핵심 |
| --- | --- | --- | --- | --- |
| 9 | GET /api/v1/me | 상단 프로필 | auth | 이름·소속·경력·배지 |
| 10 | GET /api/v1/vehicles | A① 차량 선택 | production | 시연 차량 목록 (예시 VIN) |
| 11 | GET /api/v1/vehicles/{id}/dtc-codes | A① 코드 검색 | diagnosis | 차종별 자주 검색된 고장코드 (API 2 호출마다 검색 수 +1) |
| 12 | GET /api/v1/repair-jobs | 첫 화면 오늘 작업 | record | 내 작업 20건, 진행 중이면 이어할 단계 |
| 13 | GET /api/v1/repair-jobs/{id} | 이어하기 | diagnosis → record | 작업 다시 열기 (후보·관측 비율 다시 계산) |
| 14 | PUT /api/v1/repair-jobs/{id}/cancellation | 진단 취소 | record | 상태 CANCELLED, 오늘 목록·원인 통계에서 빠짐. 완료한 작업은 409. 프론트 미연결 |
| 15 | PUT /api/v1/tasks/{id}/progress | 잠시 나가기 | record | 지금 단계·단계 기록 저장. 확인 안 한 고전압 단계를 지나면 409. 프론트 미연결 |

공통 오류는 RFC 9457 ProblemDetail(400 형식·관계없는 부품/단계, 403 다른 정비사의 작업, 404 없음, 409 상태 불일치·고전압 확인 누락). 요청·응답 전체는 [api-reference.md](./api-reference.md) (PR #18).

## 관련 정책

### 권한·안전·기록 집계 정책 (팀 설계 보드 05·06)

| 항목 | 규칙 |
| --- | --- |
| 권한 L1\~L3 (설계 제안) | L1 허용된 기본 자료 조회, L2 허가된 정비 작업·결과 기록, L3 소속 제조사 답변·집계. 인증·소유권·제조사·자료 등급을 못 채우면 401/403, 파일도 차단 |
| 버전 불일치 | 차량 사양과 절차·모델 버전이 안 맞으면 미지원 안내. 임의 절차를 대입하지 않음 |
| 3D 실패 | 같은 절차의 2D 이미지·텍스트로 대체. 색상 외에 부품명·단계 번호도 표시 |
| 고전압 확인 | 해당 작업·절차 버전의 서버 확인 기록이 없으면 다음 단계 잠금. 직접 API 호출도 같은 검증. 확인은 실제 차단 여부를 감지하지 않음 (발표 때 명시) |
| 완료 저장 | 참조·시간·권한·완료 중복을 검증한 뒤 하나의 트랜잭션으로 저장. 같은 요청 재전송은 한 건으로 처리 |
| 데이터 구분 | 시연 데이터와 실제 데이터를 구분 저장·표시 |
| 메모 공개 | 명시적 동의가 있을 때만 해당 단계 팁으로 공개, 아니면 비공개 메모 |
| 집계 | VIN·정비소·정비사 식별정보 제외. 조회 수와 완료 건수를 따로 셈 |
| 원인 비율 | 같은 사양·코드·기간에서 원인이 확인된 완료 건만 분모. 관측 비율이지 실제 고장 발생률이 아님. n이 30 이상이면 분자·n과 함께 표시하되 필수 공식 선행 순서는 유지 |
| 비교·개선 | 지표 순위는 유효 n이 10 이상부터. 사양 비교는 같은 작업 범위끼리, 인과 단정 금지. 개선 검토는 담당자가 채택·보류하고 자동 공정 변경은 없음 |
| 자료 출처 | 사용 허가·검수된 절차와 모델만 사용. 원천 CAD·공정 기밀은 저장하지 않음 |
