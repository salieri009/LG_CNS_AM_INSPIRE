# 테스트케이스 기획

> [기획서 13장](planning.md#13-테스트케이스-기획)과 같은 내용. 장 번호(6장, 14장 등)는 [기획서](planning.md) 기준이고, 배포 검증은 [EKS 배포 기획](deployment-eks.md)과 이어짐. 상태 열은 2026-11-10 기준.

2026-11-10 기준으로 실제 구현(프론트엔드 + 목 API, PR #6·#7·#8·#9)에 맞춰 고침. 시연 전에 반드시 통과시킬 P0는 17개이고, 그중 12개는 자동 테스트로 통과함. 백엔드(PR #18, Spring Boot 모듈러 모놀리스)가 올라오면서 통합 테스트 11개(H2, MySQL 모드)와 모듈 경계 테스트 1개가 생김. 백엔드 테스트는 PR #18 머지 뒤 `backend`에서 `./gradlew test`로 상태를 다시 적음. 상태는 `frontend`에서 `npm test`를 돌린 결과 기준이고, 도구와 기준 숫자는 제안이라 팀 확정이 필요함.

## 13-6. 시연 리허설 순서

1. 브라우저 목 상태 초기화: 개발자 도구에서 `localStorage.removeItem('repair-thread-mock-v1')`
2. 정비사 창(`/`)과 공장 창(`/factory`)을 나란히 띄움
3. 배포했다면 배포 검증 P0 (TC-K8S-01·02)
4. E2E 순서: TC-A1-01 → TC-A2-01 → TC-A3-01·A3-03 → TC-A4-01 → TC-B1-04 (공장 창 갱신 확인)
5. 출처 표기 확인 (TC-SRC-01)
6. 3회 연속 통과하면 시연 확정. 실패하면 그 단계의 P0 자동 테스트부터 다시

일정 (제안): 11-10 오전 경계 픽스처와 남은 P0 (TC-A2-02·03, TC-SRC-01), 시연 30분 전 리허설 1회.
