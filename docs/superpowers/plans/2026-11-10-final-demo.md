## 남은 조각 (순서·크기)

열린 PR이 3개라, 아래는 #8 위에 로컬로 쌓고 앞 PR이 머지되는 대로 하나씩 올린다.

1. 후보 점검 절차 (A② 마무리, 약 250줄)
   - 모든 후보에 2~3단계 점검 방법(측정·확인)을 둔다. 점검 결과로 "이상 없음 → 다음 후보", "이상 있음 → 원인 확정"을 고른다.
   - 원인이 확정됐는데 교체 절차가 시연 범위 밖이면 그렇다고 안내한다.
   - 3D에서는 점검 대상 부품을 강조한다.
2. 고장코드 다중 입력·증상 선택 (A①, 약 200줄)
   - 코드를 여러 개 넣으면 후보를 합쳐 공식 순서로 보여 준다.
   - 증상 칩으로 후보를 좁힌다.
3. 공장 화면 B②·B③ (약 300줄, 예시 집계)
   - B②: 같은 부품의 사양·생산 시기·라인별 평균 시간 비교.
   - B③: 고장코드별 실제 원인 분포와 몰리는 사양 탐지.
4. 시연 완성도 (약 200줄)
   - 데모 루프 5단계의 "n 48 → 49" 순간이 눈에 보이게 강조한다.
   - 3D를 나중에 불러오고 로딩 화면을 둔다 (번들 경고, 5.4MB 모델).
   - Model X 작업 기록 예시를 넣는다.
   - 빈 화면·오류 화면을 점검한다.
   - A⑤ 신입 모드는 시간이 남으면 단계 체크리스트로 넣는다.
5. 정리 (문서·검토)
   - README 데모 루프 체크.
   - api-spec에 팁 남기기 API 반영 (팀 합의 필요).
   - 발표 덱 12번 슬라이드와 화면 맞춤.
   - 마지막 검토 1회.
